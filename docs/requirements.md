# 需求说明书（草案 v0.1）

> 本文件是需求基线。任何新增 / 变更需求请提 Issue 或 PR 修改本文，并在 PR 描述中说明影响范围。

## 1. 项目背景

古籍整理长期依赖专家逐字逐句校读，效率低、门槛高。参考「荀子」古籍大模型、AI 太炎 2.0、汉典重光等实践，本项目基于 LLM/NLP 打造「机器初筛 + 专家复核」的工作台，覆盖 OCR 识别、自动标点、断句、异文校勘、文白翻译五大能力，辅助古籍整理与数字人文研究。

## 2. 目标用户

- 古籍整理者 / 出版社编辑
- 数字人文研究者
- 汉语言文学师生

## 3. 功能需求

| 编号 | 模块 | 需求描述 | 优先级 | 状态 |
| --- | --- | --- | --- | --- |
| FR-01 | OCR 识别 | 输入古籍书页影像，输出带版面坐标的文本行 | P0 | 待开发 |
| FR-02 | 文本规整 | 繁简、异体字、避讳字规范化 | P0 | 待开发 |
| FR-03 | 自动断句 | 文言文句子切分 | P0 | 待开发 |
| FR-04 | 自动标点 | 在原文插入现代标点 | P0 | 待开发 |
| FR-05 | 异文校勘 | 底本与参校本比对，输出校勘记 | P0 | 待开发 |
| FR-06 | 文白翻译 | 文言文 → 现代汉语 | P1 | 待开发 |
| FR-07 | 人工审校 | 校勘记审核界面 / 标注接口 | P1 | 待开发 |
| FR-08 | 数据导出 | 整理稿、校勘记导出（txt / json / docx） | P1 | 待开发 |

## 4. 非功能需求

- **准确性**：标点 / 断句准确率目标 ≥ 90%（参考「将无同」情境试题准确率）
- **可追溯**：每条校勘记保留版本、位置、原文依据
- **可扩展**：OCR / LLM 引擎可替换（见 `docs/architecture.md` 扩展点）
- **数据安全**：原始影像与文本不落第三方，支持配置本地 / 私有化模型

## 5. 里程碑

| 阶段 | 目标 | 交付物 |
| --- | --- | --- |
| M1 骨架 | 仓库结构、数据结构、流水线跑通 dummy 数据 | 本仓库现状 |
| M2 单点能力 | 接入首个 LLM，完成自动标点与断句 | `modules/punctuation.py`、`modules/segmentation.py` |
| M3 校勘 | 异文比对 + 校勘记生成 | `modules/collation.py` |
| M4 协同 | 审校界面 / API + 导出 | `api/`、导出模块 |
